# New Game Checklist

> The exact steps from idea to published game, in order, each with an exit condition and the skill file to open.

The 3-day schedule is the owner's target, not a sourced benchmark.
Do not skip a step marked GATE; stop and report if its exit condition fails.

## Rules

1. [Day 1 AM] List recent high-view Roblox videos, filtering by views and date before reading any transcript. Exit: a saved candidate list, all in the four proven genres (see 01, 12).
2. [Day 1 AM] Play the top candidates and read their chat or community. Exit: join reasons, stay reasons and the eight-item structure sheet written for each (see 01).
3. [Day 1 AM] Add one twist and an MVP feature list per idea, then score each on the eight axes. Exit: no idea kept that scores low on first-session clarity or mobile fit (see 01).
4. [Day 1 AM] Write the one-page brief with two or three comparables and an out-of-scope list. Exit: brief fits one page (see 01).
5. [Day 1 AM] GATE, owner approval: send the brief and scores to the owner. Exit: the owner has approved the idea; build nothing before that (see 01).
6. [Day 1 PM] Write the loop as one verb and fill the three boxes. Exit: the progression engine box is not empty (see 02).
7. [Day 1 PM] Write target KPIs and the first-week plan. Exit: D1 and playtime targets recorded; day-7 reward defined and shown from day 1 (see 11, 05).
8. [Day 1 PM] Clone the template and fill Config: names, items, save template, tunable keys. Exit: the project builds; one fixed word per currency and item (see 07).
9. [Day 1 PM] Build the tracer bullet: one action, one reward, one next goal through input, remote, server, data and UI. Exit: the balance survives a rejoin on a test data store (see 02).
10. [Day 1 PM] Play the slice alone on a phone-sized screen. Exit: first fun action reached within 10-30 seconds of spawning (see 02).
11. [Day 2 AM] Build the one new mechanic, with every remote validated and rate-limited on the server. Exit: forged and spammed requests are dropped silently (see 08).
12. [Day 2 AM] Connect progression and show short, mid and long-term goals. Exit: each upgrade visibly strengthens the core action (see 02).
13. [Day 2 AM] Build spawn and onboarding: spawn facing the first interactable, visual markers, starter grant, celebration. Exit: a full loop can be finished without reading text (see 03).
14. [Day 2 AM] Define the onboarding funnel steps and log them, plus every currency source and sink, from the server. Exit: each step and flow fires in a test session (see 11).
15. [Day 2 PM] Reskin the HUD and menu shell from Config. Exit: objective, currency, progress and next reward always visible; touch targets and text meet the minimum sizes (see 04).
16. [Day 2 PM] Add layered feedback to each core action, plus Music and SFX sliders. Exit: each action has animation, sound, effect and UI change (see 04).
17. [Day 2 PM] Switch on daily rewards, streaks and quests from Config. Exit: rejoin and retry cannot double-grant; claimable rewards badge the topbar icon (see 05).
18. [Day 2 PM] Fill the shop: durable passes, repeatable developer products, three price tiers, a starter pack. Exit: every item states effect, amount and duration; no hard-coded prices (see 06).
19. [Day 2 PM] Test purchases through the single receipt handler. Exit: grants are saved before success is reported; a duplicate receipt does not re-grant (see 06).
20. [Day 3 AM] Run the security pass. Exit: nothing secret under ReplicatedStorage; admin commands deny by default; every free asset read and quarantined first (see 08).
21. [Day 3 AM] Run the performance pass on the baseline low-end phone at lowest graphics. Exit: inside the budget; memory read from the device's Developer Console (see 09).
22. [Day 3 AM] Test with two clients, a late joiner, a respawn, a player leaving mid-action and simulated bad network. Exit: zero new errors or warnings (see 10).
23. [Day 3 AM] On a test copy, join, leave, rejoin and hop servers with two accounts. Exit: data reloads in under 5 seconds and a session end is logged (see 10).
24. [Day 3 AM] Run the break-it pass: stages out of order, out of bounds, extreme values, spammed remotes. Exit: no soft locks; death log reviewed (see 10).
25. [Day 3 AM] GATE, phone playtest: watch one first-time player on a phone without helping and time each hesitation. Exit: mobile gate passed, screenshots kept, hint delays set from the timings; no launch without it (see 10, 03).
26. [Day 3 PM] GATE, monetization policy check: odds shown before any paid random item, PolicyService checked per player, no fake urgency, pay-to-skip not the main income. Exit: every box in the 06 checklist ticked; for anything 06 does not cover, check the current Roblox policy (see 06).
27. [Day 3 PM] Fix what the tests found and re-run the failed ones. Exit: every Day 3 exit condition holds (see 10).
28. [Day 3 PM] Finish packaging: full Content Ratings Questionnaire, genre, keyword-led first sentence, 16:9 thumbnails, honest icon. Exit: the first 30 seconds of play match the packaging (see 10).
29. [Day 3 PM] Confirm the publishing fee with the owner after verifying the current policy, and set the crash-rate alert. Exit: owner confirms the budget; alert is live (see 10, 11).
30. [Day 3 PM] Publish, then join the live game on a phone. Exit: live join, core loop and save all work (see 10).
31. [After launch] Do the day-one read in order: play through rate, bounce rate, first-session retention, D1, session time. Exit: each number compared with the dashboard benchmark band; traffic checked against dashboard minimums (see 11).
32. [After launch] Fix the biggest funnel drop with one change. Exit: the cohort that joined after the change is compared with earlier cohorts (see 11).
33. [After launch] GATE, kill-or-keep review. Starting assumption (not from a source): keep if D1 and session time reach the benchmark band; kill if both stay below it after one fix cycle. Exit: keep, fix or kill recorded with date and cohort, and reported to the owner (see 11).
34. [After launch] If kept, schedule the first update: one theme, built from existing systems. Exit: update has a date (see 05).
35. [After launch] Add dated lessons to "Lessons from launched games" in each skill file the lesson touches. Exit: at least one lesson recorded, or "none" noted (see 01-12).
